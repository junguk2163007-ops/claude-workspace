# 통전⚡기사 전기기사 필기

- 실행: `dist/index.html` 더블클릭 (인터넷 없어도 동작, 글꼴만 기본 글꼴로 바뀜)
- 빌드: `node build.js` → `dist/index.html`, `dist/artifact.html`
- 테스트: `node test/run-tests.js` (템플릿당 3000문제, `N=300`으로 줄일 수 있음)
- 계산기 테스트: `node test/calc-tests.js` (설명서 예제를 키 입력 순서대로 재현)
- 화면 점검: `node test/browser-check.js [스크린샷 폴더]` (Playwright 필요)

## 구조
- `engine/` 시드 난수(rng), 숫자 표기(format), 보기 4개 만들기(choices), 4단 해설 틀(explain), 템플릿 생성(generate), 정적 문제은행(static-bank), 회로도(svg)
- `concepts/concepts.js` 과목 목록 + 회로·제어 개념, `concepts/em.js`·`power.js`·`machine.js` 과목별 개념
  (id, 이름, 그룹, 선행 개념, 개념 카드, 쉬운 비유, 공식)
- `subjects/<과목>/` 문제 템플릿과 정적(이론형) 문제: circuit, em, power, machine
- `lessons/points.js` 문제 포인트(템플릿·이론 문제마다 "이런 문제 / 풀이 핵심 / 자주 틀리는 곳"). 과목별 탭과 포인트 반복이 이걸 씀
- `lessons/` 배우기 레슨(0. 시작하기 ~ 6. 제어공학). 개념마다 레슨 1개, 예제는 실제 템플릿에서 생성
- `app/` 학습 기록 로직(progress), 저장(storage), 화면(ui), 스타일
- `test/reference.js` 템플릿과 따로 짠 독립 검산기 (새 템플릿을 넣으면 여기에도 추가해야 테스트가 통과함)

## 새 과목 추가 순서
1. `concepts/<과목>.js`에 `G.addConcepts('<과목 id>', [...])`로 개념 추가, `G.subjects`의 `ready: true`
   (과목마다 선행 개념이 없는 시작 개념을 하나 이상 둬야 테스트가 통과함)
2. `subjects/<과목>/*.js`에 `G.defineTemplate({...})`로 템플릿 작성
3. `files.js`의 `content`에 파일 추가, `test/reference.js`에 검산기 추가
4. `node test/run-tests.js` → `node build.js`

## 기록 동기화
- claude.ai 로그인 계정의 개인 저장소(`data/users/<id>/save`)에 기록을 올리고 내려받는다(`app/sync.js`). 별도 Google 로그인은 쓰지 않는다.
- 올리기 전에 서버 기록을 읽어 와서 `progress.merge`로 합친다. 통계는 더 많이 푼 쪽, 레슨·풀이 기록·복습은 합집합, 초기화(`resetAt`) 이전 기록은 버린다.
- 두 기기가 동기화 사이에 각자 푼 경우 더 적게 푼 쪽의 통계 일부가 빠질 수 있다(풀이 기록·복습·레슨은 합쳐져서 남는다).
- 파일로 열면(`window.claude` 없음) 동기화는 꺼지고 localStorage만 쓴다.

## 계산기 (왼쪽, 카시오 fx-350ES PLUS 방식)
- `engine/qnum.js` 정확한 값(분수·√·π, BigInt) / `calc-fmt.js` 액정 표시 규칙 / `calc-eval.js` 식 해석(카시오 우선순위) / `calc-stat.js` STAT 회귀 / `calc.js` 본체(키 → 화면)
- `app/calcui.js` 키패드·액정 그리기. 키 입력은 `G.calcUi.press('SHIFT')`처럼 키 이름으로 한다.
- 모드는 COMP·STAT·TABLE만 있다(이 기종에는 복소수·CALC·SOLVE가 없음). 메모리·설정은 localStorage에 저장(기록 동기화와는 별개).
- 폭 ≥1280px(AI 패널 있을 땐) 또는 ≥1000px(AI 패널 없을 땐)에 왼쪽에 붙고, 그보다 좁으면 "계산기" 버튼으로 여는 떠 있는 패널, 940px 미만(폰)에서는 숨김.

## 계산기로 풀기 (문제 옆 🖩 버튼)
- `calc-guides/*.js`: 템플릿마다 단계별 설명과 계산식(`G.guide(id, (params) => [{ say, expr }])`). 계산식은 `V/R`, `sqrt(R^2+X^2)`, `9e9*Q1*1e-6/d^2`처럼 쓰고, `engine/calc-guide.js`가 실제 fx-350ES PLUS 키 순서로 바꾼다(`$A`는 저장한 변수 A, `store: 'A'`는 결과 저장).
- `app/calcdemo.js`: 왼쪽 계산기에서 다음 키를 깜박여 알려 주고, 직접 눌러도 되고 "다음 키"·자동 재생도 된다. 시연 중엔 기본 설정(MathIO·Deg·Norm1)으로 바꿔 두었다가 끝나면 원래 설정·메모리로 복구한다.
- 새 템플릿을 만들면 같은 id로 가이드를 추가해야 `node test/calc-guide-tests.js`가 통과한다(템플릿마다 600문제를 실제 계산기에 눌러 정답과 비교). 식으로 답하는 문제(라플라스 변환 등)는 대상이 아니다.

## 용어 사전 (나무위키처럼 눌러서 보는 해설)
- `glossary/*.js`: 용어마다 `G.term(id, 이름, { aliases, brief, easy, formulas, units, exam, pitfalls, example, related, concept })`. 글 속에서 이름·별칭이 보이면 자동으로 밑줄 링크가 걸리고(`app/wikiui.js`), 누르면 오른쪽(폰은 전체 화면)에 해설 창이 열린다. 해설 안의 용어도 링크라서 계속 타고 들어갈 수 있다.
- 링크 규칙(`engine/glossary.js`): 한 카드 안에서 용어마다 첫 한 번만, 더 긴 낱말(예: 선간전압) 안의 짧은 용어(전압)는 걸지 않음, 보기·제목·공식·버튼에는 걸지 않음.
- 새 용어를 넣으면 `node test/wiki-tests.js`가 형식, 관련 용어 연결, 별칭 충돌, 예제 계산(`example.expr`를 실제 계산기에 눌러서 `ans`와 비교)을 확인한다.
- 머리글의 돋보기 아이콘 = 용어 전체 목록 + 검색.

## 처음 화면 · 검색
- 머리글의 🏠 버튼 = 처음 화면(배우기 첫 화면). 맨 위 검색창에 말을 치면 용어 해설 / 개념(레슨 읽기·단락 보기·문제 풀기) / 그 개념의 문제 유형 버튼이 나온다(`engine/search.js`, `node test/search-tests.js`).

## 메모판(전자패드)
- `app/pad.js`: 계산기 아래 손글씨 메모판. 고급 샤프처럼 가는 선(심 0.3/0.5/0.7/0.9 mm), 흑연·빨강·파랑 심, 지우개, 되돌리기, 초기화, 점 모눈 종이. 애플펜슬 등 펜은 필압에 따라 선 굵기가 변한다. 선을 좌표로 저장해서 크기가 바뀌어도 다시 그리고, 새로고침해도 남는다(localStorage `gisa-pad-v1`, 기록 동기화와는 별개).

## 수식 조판 (분수는 위아래로)
- `engine/typeset.js`: 글 속 한 줄 수식(`1/√(LC)`, `V × R₂ / (R₁ + R₂)`, `e^(−at)` …)을 분수·제곱근·위첨자 노드로 바꾼다. 단위(V/m, rad/s …), `[대괄호]` 안, 한글 낱말 사이(밑변/빗변), 공백 두 칸 이상인 구분용 슬래시, "0 / 44" 같은 진행 표시는 분수로 만들지 않는다. 한글로 쓴 식은 `수용률 = 최대 수요전력 / 설비용량`처럼 양옆에 공백이 있을 때만 분수로 본다.
- `app/mathui.js`: 화면 글자에 적용(레슨·문제·힌트·해설·용어 해설·검색 결과). 진행 표시·태그·계산기·AI 패널 등은 건드리지 않는다.
- 새 글에 공식을 쓸 때는 그냥 `A / (B + C)`처럼 쓰면 된다. `node test/typeset-tests.js`가 규칙을 확인한다.
- 수식 구간(식에 `=`나 분수·제곱근이 있는 한 줄)은 수학 글꼴(STIX Two Text)로 그리고 변수(I, V, ω₀)는 기울인다. 숫자 뒤의 단위(12 V, 5 mH), 함수 이름(sin, cos), `[대괄호]` 안 단위는 세워 쓴다. 제곱근은 윗줄이 글자에 붙고, 분수가 든 제곱근은 부호가 커진다.

## 내 기출 보관함 / 기출 CBT 반복
- `app/kigeum.js`: 사용자가 가진 기출·CBT 문제 파일(JSON: `{id, exam, s(과목 1~4), n, q, c[4], a(1~4), p(정답률), f(출제 횟수)}`)을 **이 브라우저의 IndexedDB에만** 저장한다. 사이트 코드·서버·GitHub에는 문제 원문을 넣지 않는다(공유 링크로 새지 않게).
- 가져올 때 글 속 용어(용어 사전)로 문제를 개념에 이어 붙이고, 연습 화면의 "기출 CBT 풀기", 과목별 포인트 카드 옆 "기출 CBT 반복 (n문제)"에서 푼다. 기출에는 공식 해설이 없어서 정답과 이어진 개념 공부 버튼만 보여 준다.
- 푼 기록(맞힘/틀림)은 이 브라우저(localStorage)에만 남고 기록 동기화와는 별개다.

## 전기설비기술기준 (1차)
- 기준: **한국전기설비규정(KEC) 2026.1.5 시행 개정 전문(기후에너지환경부 공고 제2025-227호)**. 한국전기산업연합회 전기설비기술기준 사이트(kec.kea.kr)의 "KEC 공고" 게시판에서 받은 공식 전문을 텍스트로 뽑아 대조했다.
- 개념 10개(`concepts/code1.js`, 1차): 전압의 구분 · 전로의 절연내력 시험전압 · 회전기·변압기·기구의 시험전압 · 접지극·접지도체 시설 · 접지도체·보호도체 굵기 · 가공전선 굵기·안전율 · 풍압하중 · 가공전선의 높이 · 지지물 간 거리 · 지지물 매설 깊이·지지선. 템플릿 14개(`subjects/code/code1.js`, `code2.js`) + 이론형 13개(`subjects/code/static.js`).
- **근거 문구 검증**: 문제에 쓴 수치마다 근거 조항(`clause`)과 공식 전문에서 가져온 문구(`quote`)를 달아 두었다. 공식 전문(저작물이라 저장소에는 넣지 않음)을 텍스트로 만든 파일이 있으면 `node test/kec-verify.js <전문.txt>`로 모든 문구가 실제 전문에 있는지 대조한다(85개 전부 일치). 파일이 없으면 건너뛴다.
- 독립 검산기(`test/reference-code.js`)는 문제 템플릿의 표와 따로, 조항을 보고 다시 옮긴 값과 조건 판정(`if` 순서)으로 답을 구해서 3000시드마다 비교한다.
- 표에서 값을 고르는 문제(`factTemplate`)는 `noCalc: true`라 계산기 풀이 버튼이 안 나오고, 계산이 있는 문제(시험전압·특고압 높이·매설 깊이·병종 풍압)만 계산기 가이드가 있다.
- 이번 1차에 **넣지 않은 것**: 저압 전로 절연저항 표(기술기준 제52조, 전기설비기술기준 고시 본문을 아직 확인 못 함), "공칭전압 → 최대사용전압" 환산(현행 KEC 본문에서 정의를 못 찾음), 수식 개체로 들어 있는 식(예: 보호도체 단면적 계산식), 접지도체 굵기에서 KEC 142.3.1의 1(구리 고압 이상 16 ㎟)과 4(고압·특고압 6 ㎟)가 서로 다르게 적힌 부분.
- 아직 없는 영역(다음 묶음 후보): 과전류 차단기·허용전류, 접근·교차 이격거리, 전선로 보안공사 세부, 피뢰시스템, 저압 옥내배선·특수장소, 전기철도, 분산형전원·태양광.

## 모의고사 · 모르겠어요 · 북마크 · 약점 개념 (레퍼런스 앱에서 배운 것)
- `app/exam.js`(화면 없는 로직) + `app/ui.js`: ∞ 문제풀이 탭 맨 위 "모의고사"로 5과목(전기자기학·전력공학·전기기기·회로이론 및 제어공학·전기설비기술기준) × 20문제 = 100문제, 150분. 번호표(과목별 5열 격자, 푼 문제·모르겠어요·현재 표시), 남은 시간, 제출 확인, 결과(과목별 점수 막대 + 과락선 40점, 평균 60점 이상이고 과락 없으면 합격권). 문제는 시드로 만들어 키만 저장해서 새로고침·나갔다 와도 이어서 풀 수 있고, 시간은 나가 있어도 흐른다.
- 제출하면 푼 기록과 복습(1일 → 3일 → 7일)에도 들어가고, 틀린 문제를 바로 다시 풀 수 있다. 시험 기록은 이 브라우저(localStorage `gisa-exam-hist`)에만 저장(기록 동기화와 별개).
- "모르겠어요" 버튼: 고르지 않고 정답·풀이를 본다. 오답으로 기록되고 복습에 들어간다. 북마크(☆): 복습 탭에서 목록으로 다시 풀 수 있다.
- 기록 탭: 약점 개념 TOP 5(3문제 이상 푼 개념 중 정답률 낮은 순, "바로 풀기") + 모의고사 기록.
- 기출 CBT 반복: 맨 위에도 "단락 보기" 버튼. 포인트가 연속 3정답으로 익숙해지면 같은 개념의 기출·CBT 최대 3문제로 이어지고(보너스 세트), 끝나면 원래 화면으로 돌아온다.
- PC 레이아웃: 오른쪽 AI 패널 폭 380 → 340 px, 양쪽 패널이 다 붙었을 땐 가운데 영역 좌우 여백을 줄였다.

## 전기설비기술기준 (2차)
- 개념 3개(`concepts/code2.js`): 과전류차단기의 동작 특성(퓨즈 gG·산업용/주택용 배선용 차단기 배수·시간·순시트립 B/C/D) · 가공전선과 건조물의 간격(저압·고압 표 332.11, 특고압 표 333.23-1과 35 kV 초과 0.15 m 가산, 보안공사 종류) · 피뢰시스템(적용 높이, 수뢰부 배치, 이격, 인하도선 간격·개수, 철근 저항). 템플릿 9개(`subjects/code/code3.js`) + 이론형 5개(`static2.js`).

## AI 질문 복습 알림
- `app/aiqa.js`: AI에게 물은 질문·답을 이 브라우저(localStorage `gisa-aiqa`)와, claude.ai에서 열었고 주인이면 아티팩트 db의 `aiqa/` 아래에 저장한다. 접근 규칙은 `aiqa` 경로를 주인만 읽고 쓰게 해 두었다(게시할 때 `capabilities.db.rules`로 선언: `{path:"aiqa", read:"owner", write:"owner"}`). 설정 탭에 저장 현황이 나온다.
- 복습 알림은 claude.ai 예약 작업 4개(한국시간 09:07 / 12:37 / 16:13 / 19:41)가 맡는다. 각 회차가 `aiqa_state/review`로 오늘 보냈는지 확인하고, 아직이면 확률(1/4, 1/3, 1/2, 마지막은 확실히)로 보낼지 정해 하루 한 번만, 매일 다른 시각에 폰 알림으로 보낸다. 보낸 질문은 `sentCount`를 올려 덜 보낸 것부터 고른다. 저장된 질문이 없으면 알림 없이 건너뛴다.

## 기출 AI 해설 · 보던 화면 계정 저장
- 기출 CBT 반복에서 답을 고르면(맞히든 틀리든) AI가 해설을 써 준다: 정답과 이유, 핵심 개념, 풀이 과정, 나머지 보기가 아닌 이유, 기억할 점. 정답은 가져온 자료를 따르되, 계산이 안 맞으면 "확인이 필요해"라고 말하게 했다. 받은 해설은 이 브라우저(localStorage `gisa-kg-expl`, 최근 300개)에 저장해 같은 문제는 다시 묻지 않는다. claude.ai에서 열지 않으면(AI 없음) 정답만 보여 주고 안내한다.
- 보던 화면은 브라우저 저장소에 더해 계정의 개인 문서(`data/users/<id>/view`)에도 저장한다. 브라우저 저장소가 비워진 경우에도 업데이트 뒤 그 자리로 돌아오고, 이때는 기록을 가져오는 동안(최대 약 2초) 첫 화면을 그리지 않아 엉뚱한 화면이 번쩍 보이지 않게 했다.

## 기출 연결 규칙 · 업데이트 내역
- `app/kigeum-rules.js`: 개념마다 정해 둔 말(강한 말/약한 말)이 문제 글에 나오는 정도로 기출을 개념에 이어 붙인다(3.5점 이상, 최대 2개, 과목 일치). 예전에는 용어 사전의 흔한 말("전압", "변압기")까지 표로 세서 엉뚱한 개념에 이어 붙었다. 규칙을 바꾸면 `kigeum.js`의 `CLS_VER`를 올려야 가진 문제를 다시 이어 붙인다. 가진 3,102문제 기준으로 못 이어진 문제는 약 1,200개로 줄이는 대신 정확도를 우선했다.
- 단락 반복(문제풀이) 배너에 "이 개념 기출 풀기 (n)" 버튼이 항상 있다.
- `app/changelog.js`: 설정 탭 맨 위 "업데이트 내역"에 나오는 글. 머리글의 업데이트 시각을 누르면 열린다. **새 버전을 올릴 때마다 맨 위에 한 묶음 추가할 것.**
